# ADR-0005: 行业分类树与供应商数据建立双向补全闭环（四象限判据 · 本轮只读）

- 状态：已接受（Accepted）
- 日期：2026-10-10
- 关联：`docs/adr/0003-shadow-table-blue-green-migration.md`（结构变更流程）、`docs/数据库设计/crm_industry_nodes-行业面主表.md`、`docs/供应商行业挂靠.md`、`scripts/gates/check-taxonomy-invariants.ts`、`scripts/gates/verify-industry-links.ts`、`scripts/ops/commodity-extension-mine.mjs`（镜像范式）
- 设计文档：`docs/superpowers/specs/2026-10-10-industry-tree-supplier-loop-design.md`

## 背景

行业树（`crm_industry_nodes`，2,080 节点）与供应商挂靠（`crm_supplier_industry_rel`，21,218 行）各自增长，但**中间没有闭环**，2026-10-10 实测暴露三类后果：

1. **树按专家单向判断长维度**：自研延伸层 `X25–X108`（84 个）的 `gap` 依据全是"国标哪里不够用"，**没有一条来自供应商证据**；结果 108 个自研节点**直接挂靠 0 个**，而库里"检测"1,062 家、"康复"1,015 家、"储能"342 家明明有主体。
2. **反向信号根本没被采集**：`crm_industry_calibration` 1,122 行里 `cannot_classify=1` 仅 33 行，理由全是"公司简介为空/信息不足"，**没有一条是"树上找不到合适类目"**——因为打标只读旧的 `supplier.industry` 自由文本（724 种，TOP23 是"A / B / C"复合桶），而从没读 `business_scope`（未挂码供应商中 41,629 家有值）。
3. **树自计数陈旧导致缺口不可见**：`supplier_count` 仅 238 个节点非 0 且与实测漂移（记 1,447 / 实 1,433），配套 `sync_counts.mjs` 还指向拆表前的旧表。

同时存在一个**会被误用的现象**：大类/中类层有 357 个整片子树零供应商（保险业、电力生产、渔业）。若把它当"覆盖不足"去补，就是 108 个死节点事故的重演路径。

## 决策

1. **缺口按四象限判定，判据必须可由 SQL 复算**，不接受主观命名归类：
   - **Q1a 子层空转**（树没错，打标没下钻）：节点直接挂靠 ≥ 200、子节点挂靠合计 = 0，**且现有子节点名分词能命中 ≥ 50% 该节点供应商的证据** → 只出"往哪个已存在子码下钻、各接多少家"的清单，**不造码**。
   - **Q1b 粗叶堆肉**（真·树太粗）：同上前提但子名命中 `< 50%` → 下切候选，父级=该节点（父为 `division` 时置 null 交人工）。
   - **Q2 无处安放**（树缺维度）：供应商有证据文本但树上无任何节点名分词命中 → 新增维度候选，父级交人工定位。
   - **Q3 钩子死挂**（不是树的缺陷）：节点直接挂靠 `= 0` 但其名称核心字块在证据文本里命中 ≥ 50 家（自研节点与国标空根都算）→ 只出"词表接码"清单，**不造节点**。自研节点里连 50 家证据都凑不齐的，单独计数不静默丢弃。
   - **Q4 目录无此主体**（不算缺口）：国标子树零供应商且无文本证据 → 标"保留权威覆盖"，**永不自动生成候选**。空根只算**最上层**（父也空则由父代表），而门类没有父，整片空掉时必须自己成为空根（否则一整个空门类连同它的空子树会从指标里消失）。
   - 产出按性质分三组：**接线类（Q1a+Q3）／造码类（Q1b+Q2，需人工勾选）／保留类（Q4）**。
2. **权威完整度与业务覆盖度拆成两个正交指标**，不互相污染：国标节点零挂靠不作为 KPI 扣分项，也不作为扩树理由。
3. **词表 SSOT 是树自身**，不读站外 `keyword-rules-v4.json`；命中优先级沿用门户已有口径（官方名优先、释义只兜底），三态归类 `by-name / desc-only / unmatched`。词表**分两套用途**：
   - **归类用窄词表**（名整串分词）：保证 Q2 是保守下界，不因泛词乱命中而把真缺口说成"已覆盖"；
   - **归因用宽词表**（名核心字块）：因为自研节点名普遍是长串（「第三方检验检测认证TIC」），只用整串则经营范围里写「检测」的 1,062 家永远命中不了，Q3 会把**真有主体**的新兴产业误判成"目录无此主体"。
   - 宽词表必带三道泛词门（阈值均由 2026-10-10 实测定）：归属节点 ≤ 20（卡住 `制造` 662 / `设备` 154 / `机械` 47）、拉丁串只取整个缩写（否则 `FinTech` 拆出的 `IN/ES/TE` 在英文品名里打到 44%）、语料频率 ≤ 5% 文本（卡住毫无区分度的 `医疗` 13%、`器械` 12.5%）。
4. **度量一律实时从 `rel` 聚合，不读 `supplier_count` 列**；该列与实测的漂移节点数本身作为一条健康指标报出。刷新该列属写操作，另批处理。
5. **本轮只交付"度量 + 挖掘"两环，零写库**：只读守卫三层（`START TRANSACTION READ ONLY` + SQL 语句白名单断言 + 无 `--apply` 参数）。造码入库、词表接 X 码、重打 rel、回填主码全部留待人工勾选候选后的后续批次。
6. **候选清单必须自带证据与反冗余剔除**：每条含去重供应商数、词频、≥3 家样本、可复算 `gapNote`；候选名与父同名/被父包含即剔除；父为 `division` 时不得产出挂载建议（镜像门禁 I5/I6）。

## 后果

- 2026-10-10 首轮实测：Q1a 子层空转 1 个粗码（`UGT-I-032308` 医疗仪器 7,124 家，**现有子码已能解释 92%** → 不需造码，只需下钻）；Q1b 下切候选 271 条、Q2 新增维度候选 160 条；**Q3 死钩子 724 个（自研 101 / 国标 623），涉及去重供应商 33,507 家——即这些主体完全可以用已有码挂上去，一个节点都不必新增**；Q4 保留 240 个分支（国标最上层空根共 863：小类 614 / 中类 218 / 大类 30 / 门类 1）。
- 正面：扩树从"猜"变成"证据驱动"；Q1a、Q3、Q4 三道防线把"造了也没人挂"与"给已切好的类目再造同义码"两类失败卡在造码前；权威覆盖与业务覆盖两个指标不再互相侵蚀；只读探针可反复执行，形成下一轮扩树的基线。
- 代价：Q2 判据以树名为词表，属**保守下界**（同义词仍可能漏判），因此候选必须经人工勾选才能进树；全目录文本匹配要建 Aho-Corasick 自动机（无依赖自实现），脚本运行时长从秒级升到数十秒级（不进 CI 主作业，与 `check:taxonomy` 同为按需/部署后执行）。
- 边界：本 ADR 不改动树结构、不改动门户消费链路、不改 `verify-industry-links.ts` 既有底线/目标线；与挂靠侧（站外/内网 `_cloud` 表）的「内网→云端回流缺口」仍是独立未决项。

## 替代方案（已否决）

- 零挂靠即视为缺口、一并补齐：会让候选清单混入大量造了也没主体挂靠的维度，正是现有 108 个死节点的成因，否决。
- 把四象限并入 `verify-industry-links.ts`：单文件职责膨胀，且挖掘需全表文本扫描与门的节奏不同，否决。
- 在 `supplier` 上建 FULLTEXT ngram 索引做库内词频：属跨仓契约的 DDL 且违反本轮零写库，否决。
- 直接让大模型自由生成候选节点：无证据锚定，不可复算、不可审计，否决。
