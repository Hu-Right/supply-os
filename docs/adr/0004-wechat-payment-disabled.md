# ADR-0004: 微信支付渠道停用与启用前置条件

状态：已接受 · 日期：2026-08（依据代码与提交历史整理）

## 背景

支付层最初实现了微信支付 Provider（WechatProvider）骨架，但回调验证与生产配置从未在真实环境验证过。数据库核查（2026-08-30）确认：线上仅有 alipay/live 渠道启用，微信渠道零用户、零订单，相关 stub 代码存在回调验签缺陷。

## 决策

1. 微信支付保持**停用**状态（`crm_payment_provider_configs` 不启用 wechat 渠道）；
2. PaymentService 侧保留 provider 接口与 WechatProvider 代码路径，但生产 fail-fast 校验（instrumentation P21）确保配置不完整时拒绝启动支付能力；
3. 若未来启用微信支付，需先补齐以下**前置条件**：
   - 回调验签真实联调（含 TRADE_CLOSED 退款通知路由，见 F20 实现）；
   - 商户号/APPID/证书密钥管理与轮换方案；
   - 回调地址安全（notify_url 白名单）与幂等消费验证；
   - 与支付宝对账相同的对账/差错处理流程。

## 后果

- 零微信用户（~27 名 alipay/live 用户不受影响）；
- 微信相关 stub 缺陷不构成线上风险；
- 启用成本被显式记录为前置条件清单，避免带病上线。
