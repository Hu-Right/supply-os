# 权益体系重新设计（档位体验与矩阵）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按 `docs/superpowers/specs/2026-09-25-权益体系重新设计-档位体验与矩阵设计.md` 把权益体系重设计落地：重构权益目录与矩阵取值、补齐详情页六大 Tab 的档位门控与中文报告门控、订制服务 Tab 过滤，并同步校验门禁与六语言。

**Architecture:** 原生权益模型单轨——`crm_benefit_catalog` 定义权益、`crm_plan_benefits` 逐格取值、`benefit-system.repo` 的 `resolveGates/isEntitled/levelForUser` 为唯一门控入口、详情页 Tab 角标由服务端派生下发、前端只渲染。本轮只落"矩阵取值 + 展示门控"，高级搜索/关键词库/主动推送等真实功能后续补。

**Tech Stack:** Next.js App Router、TypeScript、MySQL(mysql2)、Vitest、i18n 六语言(zh/en/es/fr/ru/ar)。

**关键约束（务必遵守）：**
- 本机 `127.0.0.1:3307` 直连生产；**迁移文件只写不擅自跑**，执行前人工确认。
- 迁移幂等（`INSERT ... ON DUPLICATE KEY UPDATE` / `UPDATE`）。
- 退役权益用 `is_active=0`，**不删行**（`tech_support`/`procurement_consult` 被服务目录 `grant_benefit_code` 外键引用）。
- 每个改 `crm_benefit_catalog`/`crm_plan_benefits`/`crm_service_catalog` 数量的动作，都要同步 `scripts/verify-benefit-constraints.ts`。
