# 权益体系重新设计 · 档位体验与权益矩阵（设计文档）

- 日期：2026-09-25
- 状态：待用户审阅
- 范围：会员套餐（个人版 / 企业版）+ 详情页六大 Tab + 定制服务 + 免费档口径；权益体系八表（`crm_plan_catalog` / `crm_benefit_catalog` / `crm_plan_benefits` / `crm_plan_subscriptions` / `crm_benefit_quotas` / `crm_subscription_seats` / `crm_service_catalog` / `crm_service_orders`）的目标取值与展示规则。
- 关系：本文**取代** m097（`097-plans-chinese-gating`）的取值口径；m097 已上生产，本设计用新迁移覆盖其差异。

## 1. 背景与目标

老板白板定价 + 多轮讨论后，决定把权益体系**当白纸自上而下重新设计**：先定"每档登录后完整能做什么"的体验，再让权益清单从体验里长出来，最后用八表精确表达。不是往旧的 21 个权益码上打补丁。

三条硬约束：
- 权益体系**原生模型单轨**，不设"旧码→新码"翻译层、不加多余中间层。
- 详情页 Tab 角标一律由服务端 `resolveGates` 按矩阵派生下发，**前端不复制档位常量**。
- 解锁配额消费收敛到 `unlock-quota` 唯一记账口径。

## 2. 档位结构（crm_plan_catalog）

| plan_code | 名称 | 价格 | 归属 | 状态 |
|---|---|---|---|---|
| free | 普通用户 | 0（不售卖） | 兜底基线 | 保留（is_active=0） |
| starter | 体验版 | 129 | 个人版 | 在售 |
| pro | 专业版 | 999 | 个人版 | 在售 |
| unlimited | 无限版 | 1299 | 个人版 | 在售（most_popular） |
| business | 企业智能版 | 8800 | 企业版 | 在售 |
| advisor | 企业顾问版 | 36800 | — | **下架**（is_active=0，老订阅到期前权益不变） |
| enterprise | 机构/API版 | 联系销售 | — | **下架**（is_active=0） |

- **企业版只保留 8800 一个订阅档**；199 不是订阅（见 §8）。
- 个人三档价格与解锁额度不变（10 / 100 / 不限）。

## 3. 权益目录（crm_benefit_catalog）目标集

围绕"体验"重新归组，共 17 枚进矩阵，另有 2 枚"人人可用不进矩阵"、5 枚移出到定制服务。

**A 浏览与解锁**
1. `global_search` 标讯搜索/浏览
2. `notice_view` 解锁额度（次，计量）
3. `notice_original` 查看公告原文（解锁后，源语言）

**B 中文与 AI 加工**
4. `notice_translation` 整篇中文翻译
5. `ai_summary` AI 采购摘要（enum：0 无 / 1 部分脱敏 teaser / 2 完整）
6. `ai_match` AI 适配评估（enum，8800 为企业级）

**C 标讯深度信息**
7. `notice_qualification` 资格条件（解锁门控）
8. `notice_files` 原始文件下载（解锁门控）
9. `history_notice_db` 历史中标
10. `similar_opportunity` 相似机会
11. `chinese_bid_report` 中文版订单拆解报告下载（归入"中文报告"，1299+；实现可直接复用 `notice_translation`/中文能力门控，不必新增码）

**D 检索与组织（本轮先标卖点，真实功能后补）**
12. `advanced_keyword_search` 高级关键词搜索
13. `favorite_notice` 收藏公告
14. `proactive_alert` 主动推送 / 监控（提醒服务）
15. `product_keyword_lib` 产品关键词库

**E 企业协作**
16. `enterprise_profile` 企业画像 / 企业级匹配
17. `joint_bid_match` 联合投标资源匹配
（多席位由 `crm_plan_catalog.seat_limit` + `crm_subscription_seats` 承载，不占权益码）

> **说明：解锁门控项 ≠ 按档差异化权益。** 上表 A/C 组的 `notice_original`（查看原文）、`notice_qualification`（资格条件）、`notice_files`（原始文件下载）本质是"**消耗 notice_view 解锁后即可查看**"，对所有档位行为一致，不按档差异化；实现上它们沿用详情页 `kind:"unlock"` 门控，**不需要各自建按档取值的矩阵格**（列出仅为体验完整表达）。真正需要按档逐格取值的是：`notice_view`、`notice_translation`、`ai_summary`、`ai_match`、`history_notice_db`、`chinese_bid_report`、`advanced_keyword_search`、`proactive_alert`、`product_keyword_lib`、`enterprise_profile`、`joint_bid_match`（`global_search`/`similar_opportunity`/`favorite_notice` 全档 ✓）。

**人人可用、不进矩阵（不作差异化）**
- `source_url_view` 原始来源网址（指向公开官方公告页的外链，人人可点）
- `unspsc_cpv` UNSPSC/CPV 类目筛选辅助（所有用户可用）

**移出矩阵 → 归"定制服务"（crm_service_catalog，另类收费服务）**
- `ai_tender_analysis` AI 单标解析（= ¥199/单 服务）
- `expert_consult` 专家人工咨询（= ¥16,800/年 服务）
- `dedicated_advisor` 专属顾问（营销项，无对应功能）
- `tech_support` 投标技术支持次数（= ¥3,000/年 服务包额度）
- `api_access` API 接口（机构/API 档卖点，随该档下架一并移出矩阵）

## 4. 权益矩阵（crm_plan_benefits 目标取值）

✓=已含 / ✗=不含（仅升级引导，不露数据） / teaser=部分脱敏样例 / 需解锁=消耗 notice_view 后可看 / 数字=额度

| AI 适配评估 | ✗ | ✗ | ✗ | ✓ | 企业级 |
| 资格条件 | 需解锁 | ✓解锁后 | ✓ | ✓ | ✓ |
| 原始文件下载 | 需解锁 | ✓解锁后 | ✓ | ✓ | ✓ |
| 历史中标 | ✗ | ✗ | ✓ | ✓ | ✓ |

| 中文版拆解报告下载 | ✗ | ✗ | ✗ | ✓ | ✓ |

| 收藏公告 | ✓ | ✓ | ✓ | ✓ | ✓ |

| 产品关键词库 | ✗ | ✗ | ✗ | ✗ | ✓ |

| 联合投标资源匹配 | ✗ | ✗ | ✗ | ✗ | ✓ |

关键分界：
- **129 vs 999 的唯一差异 = 历史中标**（999 有、129 无）。
- **999 vs 1299 的分水岭 = "中文 + AI"**：整篇中文翻译、AI 摘要（完整）、AI 适配评估、中文报告下载、高级关键词搜索，全部从 1299 起。
- **1299 vs 8800 的分水岭 = "企业协作 + 检索组织"**：多席位、企业画像/企业级匹配、联合投标、主动推送、产品关键词库，8800 专属。

## 5. 详情页六大 Tab 展示与门控规则

Tab 顺序与门控来源（`DETAIL_TABS`）：

| Tab | 门控来源 | free | 129/999 | 1299+ |
|---|---|---|---|---|
| 采购摘要 | `ai_summary` | 隐藏/锁（无数据） | **teaser**：露"采购内容"整段 + 资格条件截断 200 字，竞争/策略/风险/账期打码 + "需升级"角标 | 完整六维 |
| 资格条件 | 需解锁（`notice_view`） | 锁（无额度→需升级/需解锁） | 解锁后完整（含中文字段，走 Y 口径） | 同 |
| 原始文件 | 需解锁 | 锁 | 解锁后：原件下载 + 外链 | 同 |
| AI 适配评估 | `ai_match` | 锁 | **走法②**：仅"升级解锁"引导，不露任何评分数据 | 完整（8800 企业级） |
| 历史中标 | `history_notice_db` | 锁 | 129 锁 / 999 完整 | 完整 |
| 相似机会 | `similar_opportunity` | ✓ | ✓ | ✓ |

其它规则：
- **"只看原文"定义**：129/999 解锁后，正文只有源语言原文（无整篇中文翻译）、无完整 AI 报告；但结构化字段（资格条件，可能中文）与原件下载照给（Y 方案）。
- **中文版订单拆解报告（docx）**：归入"中文报告"，**仅 1299+ 可下载**；129/999 即使在"已解锁"区也不给下载入口。
- **原始来源网址**：人人可点，不按档卡。
- 所有角标（已包含/需解锁/需升级/免费/联系）由服务端 `resolveGates` 派生，前端只渲染。

## 6. 免费档（普通用户）口径

- 定义 = `plan_code='free'` 列，未登录与"已登录无生效订阅且非他人席位"一律 fallback 到该列。
- 能：搜索/浏览标讯列表、进详情看锁定态、看**相似机会**、**收藏**公告。
- 不能：解锁任何公告（额度 0）、看原文全文、看摘要/AI/中文/历史中标/报告下载。
- 免费档 `ai_summary=0`（本轮变更：从 m097 的 1 降到 0）。

## 7. 定制服务与 199

- **"订制服务"Tab 只展示 `advisory`（顾问服务）+ `api_license`（API 数据授权）两类**；`pro_service` 类不在该 Tab 出现。
- **199「1:1 人工找单」= 服务，不是订阅**：留在 `crm_service_catalog`（`svc_manual_bid_match`），不进权益矩阵、不建订阅、不给平台权益，交付为人工撮合（"有一单的机会"）。
- 199 **只针对企业**：在**企业 Tab** 与 8800 并列展示（`EnterpriseCompanionCard`）；因它属 `pro_service`，天然不出现在"订制服务"Tab，与上面过滤规则吻合。
- 甲类 5 项（AI单标解析/专家咨询/专属顾问/技术支持次数/API接口）作为另类收费服务归入服务目录。

## 8. 与现状（m097）的差异（新迁移需覆盖）

| 项 | m097 现状 | 本设计目标 |
|---|---|---|
| free `ai_summary` | 1（脱敏可看） | **0（不给）** |
| starter/pro `ai_summary` | 0 | **1（teaser）** |
| 收藏 vs 监控 | 单一 `favorite_monitor` | **拆成 `favorite_notice`(人人) + `proactive_alert`(8800)** |
| `advanced_keyword_search` | 各档有值但无功能 | 1299+ 卖点（功能后补） |
| `source_url_view` / `unspsc_cpv` | 矩阵有行 | 移出差异化（人人可用） |
| 甲类 5 项 | 在矩阵内 | 移出矩阵 → 服务目录 |
| 中文报告下载门控 | 仅按解锁 | **加档位门控：1299+ 才可下载** |
| 企业档 | advisor/enterprise 已 is_active=0 | 保持下架；企业订阅只剩 business(8800) |

## 9. 分期（本轮范围 vs 后续）

- 权益目录重组（新增/拆分/移出）、矩阵取值、免费档收紧、中文报告下载门控、订制服务 Tab 过滤、企业 Tab 199 并列（已完成）。

**后续（真实功能，本文只标卖点，不在本轮实现）：**

- 收藏数量/监控上限的按档门控。

## 10. 风险与待办

- **写生产**：本机 3307 直连生产，新迁移执行前须人工确认（沿用 m097 的闸口纪律）。
- **矩阵闭合门禁**：权益目录增删会改变 `verify-benefit-constraints.ts` 的绝对值（benefits/cells/services），须同步更新，否则 CI 红。
- **旧码退役**：甲类移出矩阵、`favorite_monitor` 拆分等，须守卫下游引用（服务订单 `grant_benefit_code`、对比表行、i18n 六语言键）。
- **i18n**：新权益名/Tab 文案需六语言（zh/en/es/fr/ru/ar）同步。
- **teaser 边界**：129/999 的摘要 teaser 是中文内容，与"只看原文"是刻意的"钩子例外"，需在文档与实现注释里写明，避免被当成漏洞"修掉"。
