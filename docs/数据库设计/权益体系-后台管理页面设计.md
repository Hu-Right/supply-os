# 权益体系 — 后台管理页面设计（intelligence-daily）

> 承载项目：`intelligence-daily`（Vue 3 + Element Plus + vue-router 分组菜单 + `v-permission` 权限码 + server `modules/*`）。
> 数据事实源：`docs/数据库设计/权益体系-数据库设计总览.md` 及 8 张权益体系表文档（表名已去掉年份后缀，文件名按「表名-功能」）。
> 页面/菜单/权限码中的 `NEO 2026` 为**产品品牌名**（源需求文档 `OS_NEO_SMART_2026官网正式价格体系_V1.0.docx`），与数据库表名无关，保留不改。
> 边界纪律：本套页面全部在后台项目内；supply-os 门户**只读矩阵/额度，永不提供写端点**（Supply OS 不承载管理员功能）。

## 1. 菜单与路由挂载

沿用现有「订单与财务」分组（`path: 'orders'`, meta `{ title: '订单与财务', icon: 'Money' }`），新增子分组**「NEO 2026 权益」**：

```
订单与财务 /orders
  ├─ …（既有：研修班订单/学习区订单/套餐解锁订单/会员套餐配置/支付渠道配置）
  └─ NEO 2026 权益 /orders/neo2026            meta: { title: 'NEO 2026 权益', icon: 'VipCard' }
       ├─ benefit       权益目录        OsNeoBenefit.vue          views/orders/
       ├─ plan          套餐目录        OsNeoPlan.vue             views/orders/
       ├─ matrix        权益矩阵编辑器  OsNeoMatrix.vue           views/orders/
       ├─ subscription  套餐订阅        OsNeoSubscription.vue     views/orders/
       ├─ quota         额度账本        OsNeoQuota.vue            views/orders/
       ├─ seat          订阅席位        OsNeoSeat.vue             views/orders/
       ├─ service       增值服务目录    OsNeoService.vue          views/orders/
       └─ service-order 服务订购订单    OsNeoServiceOrder.vue     views/orders/
```

server 侧新建 `modules/neo-membership`（与旧 `modules/membership` 并存至旧表下线），
DTO/枚举常量放 `packages/contracts`，**前端下拉选项与后端校验共用同一份枚举**（防止旧体系 `RANK_OPTIONS` 前端硬编码漂移问题重演）。

## 2. 全局写操作纪律（由表结构直接推导，页面不得绕行）

| 结构约束 | 页面行为要求 |
|---|---|
| 矩阵 `chk_one_value`（三值列恰好一个非空） | 编辑器**不提供"留空"**；`—` 必须显式选"无(0)"；值输入控件按字典 `value_kind` 切换，切不动=没选对类型 |
| 矩阵"全笛卡尔积"完整性 | 新增权益/新增套餐后矩阵出现**红色空格**，空格状态下禁止保存该套餐，直至补格（补格=一次事务批量 INSERT） |
| 套餐/目录"调价=新版本行+旧行下架" | 已成交（被订阅/订单引用）的行**隐藏删除与价格编辑**，只给「复制为新版本」和「下架」按钮 |
| 订阅"只 INSERT + 状态列 UPDATE" | 订阅页无编辑按钮；仅「状态流转」（人工终止/退款登记），且必须填原因走 `modules/audit` 审计 |
| 额度唯一扣减口径在门户服务层 | 后台**没有任何"加额度/减额度"输入框**；仅只读账本 + `frozen/unfrozen` 状态操作（冻结走统一服务函数，不直改行） |
| `seat_limit` 快照校验在事务内 | 席位页新增成员由 server 校验 `COUNT(active) <= seat_limit`，超限返回业务错误码，前端原样 toast |
| 订单 `status`/`sale_mode_snapshot` 无默认值（VARCHAR+CHECK 取值域） | 表单对应控件**无初始值、必填**，禁止“默认选中第一项”；DB 已实测会直接拒绝漏传与非法值 |

## 3. 页面逐项描述

### 3.1 权益目录 `OsNeoBenefit.vue`（表：`crm_benefit_catalog`）

- **列表列**：`benefit_code`（主键直显）｜`name_zh`｜`group_code`（tag）｜`value_kind`（tag：布尔/枚举/额度/金额）｜`is_consumable`（开关态）｜`sort_order`｜`is_active`｜操作。
- **筛选**：关键词（码/名）+ `group_code` 下拉 + `value_kind` 下拉。
- **新增/编辑对话框**（`el-dialog`，宽 560px）：
  - `benefit_code`：新增必填、**编辑禁用**（主键即语义）；
  - `value_kind`：`el-select`（contracts 枚举）；编辑态改值类型 → 二次确认弹窗（"将影响 N 个矩阵格"，server 返回引用数）；
  - `level_dict`：仅 `value_kind='enum'` 显示；**结构化行编辑子表**（level 整数 + 中文含义两列，动态增删行），序列化为 JSON 提交——不允许裸文本框填 JSON；
  - `is_consumable`：`el-switch`；`gate_key`：文本（可空）；`sort_order`：`el-input-number`。
- **删除策略**：无删除按钮；仅「停用」（`is_active=0`），server 拒绝停用仍被活跃矩阵引用的权益。
- **权限码**：`neo:benefit:view / add / edit / disable`。

### 3.2 套餐目录 `OsNeoPlan.vue`（表：`crm_plan_catalog`）

- 沿用 `OsMembership.vue` 页面骨架（header + toolbar + table + pagination + dialog + drawer），差异在列与表单：
- **列表列**：`plan_code`｜`name_en`+`name_zh`｜`price`（`price_mode='contact'` 显示"联系销售"而非 ¥0.00——**渲染分支由快照列驱动，禁止前端猜**）｜`commercial_tier`（L1-L6 tag）｜`seat_limit`（-1 显示"合同自定义"）｜`badge`｜`is_active`｜操作。
- **表单控件映射**：
  - `price_mode`：radio（明码/联系销售）；选"联系销售"时 `price` 输入框禁用并置 0；
  - `price_incl_tax`：radio（含税/未税/**未定 NULL**三态，用 `el-radio-group` + 显式"未定"选项，不用可清空的 select）；
  - `seat_limit`：`el-input-number`（min=1）+ 独立 checkbox「合同自定义(-1)」，勾选后数字框禁用；
  - `badge` / `cta_i18n_key` / `commercial_tier`：contracts 枚举下拉；
- **操作列**：详情｜编辑（未成交时）｜**复制为新版本**（已成交后唯一改价路径，预填全字段、`plan_code` 需新值）｜下架。
- **详情抽屉**：`el-descriptions` + 嵌入该套餐的**矩阵切片**（只读，来自 3.3 接口），运营在一页内看全"这档到底给了什么"。
- **权限码**：`neo:plan:view / add / edit / clone / disable`。

### 3.3 权益矩阵编辑器 `OsNeoMatrix.vue`（表：`crm_plan_benefits`）★ 新页面类型

全系统唯一的**表格编辑器（editor grid）**页，不用 CrudPage 模式：

- **布局**：`el-table` 行=权益（按字典 `group_code` 分组、`sort_order` 排序，组头行合并单元格），列=六档套餐（`plan_code` 表头显示 `name_en`）；每格一个内联编辑控件。
- **格子控件按 `value_kind` 动态渲染**（读字典接口，前端零硬编码）：
  - `bool` → 勾选框（0/1）；
  - `enum` → `el-select`，选项来自该权益 `level_dict`（显示"2 - 标准/完整"，**提交整数**）；
  - `quota` → 数字框 + 「不限」checkbox（勾选即提交 `-1`，数字框禁用）；
  - `amount` → 金额框（precision=2）+ 「包含(0.00)」快捷按钮；
  - 每格 hover 显示 `note_zh` 编辑气泡（格备注，docx"边界口径"的维护入口）。
- **完整性视觉**：缺格红底 + 页顶徽标"矩阵不完整：N 格待补"；不完整时**整个套餐列头禁止上架**（server 同步校验）。
- **保存模型**：单元格失焦即暂存到页面态，右上角「保存变更」批量提交 diff（`{plan_code, benefit_code, value}` 数组），server 单事务逐格 UPDATE + 审计记录（谁改了哪格）；**放弃按钮**还原。
- **单调性提示**：同一权益行若高档值低于低档值，黄色警示（可保存——"可配置/定制"允许合同例外，只提示不阻断）。
- **权限码**：`neo:matrix:view / edit`（edit 单独授权，比套餐编辑更高危）。

### 3.4 套餐订阅 `OsNeoSubscription.vue`（表：`crm_plan_subscriptions`）— 只读 + 状态流转

- **列表列**：`id`｜`owner_user_id`（可跳用户详情）｜`plan_code`（tag）｜`source_order_no`（可跳订单）｜`price_paid`｜`seat_limit`｜`status`｜`started_at`/`expires_at`｜`replaced_by_id`（链指针，点击跳承接单）。
- **筛选**：用户 ID/订单号/套餐/状态/到期时间段。
- **无新增、无编辑**（订阅只能由门户支付流程产生——后台"送订阅"被结构纪律禁止，见订阅表文档 `source_order_no NOT NULL`）。
- **行操作**：仅「状态流转」dialog：目标状态（cancelled/refunded 两个人工项）+ 原因（必填 textarea）+ 影响预览（server 返回：将冻结 N 条额度、移出 N 个席位），确认后同事务执行。
- **权限码**：`neo:sub:view / terminate`（terminate 属高危，独立授权 + 审计）。

### 3.5 额度账本 `OsNeoQuota.vue`（表：`crm_benefit_quotas`）— 只读 + 冻结

- **列表列**：`subscription_id`｜`seat_user_id`｜`scope`（tag：订阅共享/席位独立）｜`benefit_code`（显示权益目录中的名称）｜**进度条列**：`quota_used / quota_total`（`-1` 渲染"不限"标签，无进度条）｜`period` + `period_starts_at`｜`status`。
- **筛选**：用户/权益码/周期/状态；默认 `status='active'`。
- **行操作**：仅「冻结 / 解冻」（带原因，走统一服务函数；`exhausted/expired` 行无操作）。
- **聚合视图**（页内 tab）：按 `benefit_code` 汇总全库消耗水位（财务/AI 算力成本观察），纯查询不落新表。
- **权限码**：`neo:quota:view / freeze`。

### 3.6 订阅席位 `OsNeoSeat.vue`（表：`crm_subscription_seats`）

- 入口双形态：独立列表页（按订阅筛选）+ 订阅详情抽屉内嵌子表。
- **列表列**：`subscription_id`｜`member_user_id`｜`is_owner`（tag"主账号"）｜`status`｜`joined_at`/`removed_at`。
- **操作**：「添加成员」（server 校验席位上限，超限错误码 `SEAT_LIMIT_EXCEEDED` 前端 toast）、「移出」（confirm + 原因）；owner 行无移出按钮。
- **权限码**：`neo:seat:view / add / remove`。

### 3.7 增值服务目录 `OsNeoService.vue`（表：`crm_service_catalog`）

- **列表列**：`service_code`｜`name_zh`/`name_en`｜`category`（三类 tag）｜**价格列复合渲染**：`standard_price` + `price_mode` 后缀（"/单 /次 /年 Token 起价 报价 联系销售"，由枚举映射，前端不拼字符串）｜`sale_mode`｜`member_discount`｜`is_active`。
- **表单联动**（全部由字段语义驱动，无自由文本区）：
  - `price_mode` 下拉 → `project/quote/contact` 时 `standard_price` 禁用置 NULL；
  - `price_from`：仅 `standard_price` 有值时可勾；
  - `grant_benefit_code`：下拉只列字典中 `is_consumable=1` 的权益；选中后 `grant_quota`（必填正数）与 `grant_period`（必填非 none）解锁——对应 `chk_grant_pair`/`chk_grant_period`；
  - `sale_mode='contract'` 时表单顶部提示条："本服务成交必须回填 `contract_ref`"（订单页强制项的预告）。
- **权限码**：`neo:service:view / add / edit / disable`。

### 3.8 服务订购订单 `OsNeoServiceOrder.vue`（表：`crm_service_orders`）

- **列表列**：`order_no`｜`user_id`｜`service_code`｜`quantity`×`unit_price_snapshot`=`amount_total`｜`sale_mode_snapshot`｜`status`（状态机 tag）｜`contract_ref`｜`paid_at`。
- **筛选**：单号/用户/服务/状态/时间。
- **操作按状态机渲染**（与订单表文档第 4 节迁移表一致）：
  - `lead` → 「转报价」（填 `unit_price_snapshot` → `pending`）；
  - `pending` → 「登记成交」（`contract` 形态必填 `contract_ref`；`self` 形态成交来自支付回调，后台**无** paid 按钮，只可 `cancelled`）；
  - `paid` → 「退款登记」（同事务联动额度 `frozen`，二次确认列出将冻结的池行）；
- **权限码**：`neo:sorder:view / quote / settle / refund`（refund 高危独立授权）。

## 5. 接口面约定（server `modules/neo-membership`）

- 每页一组 REST 资源：`/api/neo/{benefits|plans|matrix|subscriptions|quotas|seats|services|service-orders}`；
- 写接口一律 server 端重校验（ENUM 取值、CHECK 语义翻译为业务错误码：`MATRIX_CELL_INCOMPLETE`、`SEAT_LIMIT_EXCEEDED`、`PLAN_PRICE_LOCKED`…），**前端控件只是体验层，不是约束层**；
- 矩阵保存接口接收 diff 数组，单事务执行并写审计（`modules/audit`）；
- 枚举类下拉（value_kind/group/price_mode/状态机）统一从 `/api/neo/meta/enums` 取 contracts 常量，前端零枚举副本。
