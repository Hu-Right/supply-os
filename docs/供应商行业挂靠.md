# 供应商行业挂靠 · 后端交接（2026-10-09）

## 0. 一句话职责

你负责**"供应商 ↔ 行业"挂靠数据的写入与质量**：向 `crm_supplier_industry_rel`（多行业挂靠）和 `supplier.industry_code`（主行业码）写数据。
行业树本身（`crm_industry_nodes`）对你**只读**——造码/改树走独立管线，不归挂靠侧。

## 1. 表与读写边界

| 表 | 角色 | 你能做什么 |
| --- | --- | --- |
| `crm_industry_nodes` | 行业权威树（2,080 节点，仍在扩充） | **只读**。缺类目时提需求，走 `runtime/add-industry-nodes.mjs` 造码，禁止手 INSERT |
| `crm_supplier_industry_rel` | 多行业挂靠桥表 | **主战场**，INSERT/按需清理 |
| `supplier.industry_code` | 主行业码（单值） | 写：必须是该供应商挂靠中证据最强、最深的码 |
| `supplier.industry` / `industry_id` | 旧自由文本 / 旧站外 ID | 只读遗留，禁止回落使用、暂不清洗删除 |

门户读口径（写数据时务必对齐）：**可见供应商 = `verify_status='done' AND company<>'测试'`**。门户下拉、筛选、卡片标签只统计这个口径。

## 2. 硬规则（红线，门禁会抓）

1. `industry_code` 必须存在于 `crm_industry_nodes.code`——野码会让探针 X2/X4 变红（挂靠孤儿/主码孤儿）。
2. **主码必须同时在挂靠表里**（底线 ≥99%，当前 100%）。顺序：先挂 rel、再回填主码。
3. 同一 `supplier_id + industry_code` 不重复挂（用 `INSERT IGNORE` 或先查后插）。
4. 只挂这些 level：`subclass`/`extension`（优先，产品级证据）、`group`（行业级证据）、`division`（兜底，confidence ≤0.7 并标待精化）。**禁止挂 `section`**。
5. 字符集 `utf8mb4` / `utf8mb4_0900_ai_ci`；跨表 JOIN 不要手写 COLLATE。
6. `crm_industry_nodes.src_code` 是展示注记（2026-10-09 已重排为父节点内顺排号），**任何逻辑不得把它当码用**；重排前的国标原码对照只在 `runtime/industry-src-renumber-backup-2026-10-09.json`。
7. 批量写入单事务、失败回滚；挂靠表行数底线 20,000。大规模重算前先备份（表级备份命名 `__bak_<用途>_<日期>`，库里已有先例）。

## 3. 打标深度规则（决定质量目标线能否达标）

证据分级：

- 公司名/产品文本命中**产品词**（"手术刀""eVTOL""X 光机"）→ 挂**小类（subclass）或自研延伸层（extension，X 码，共 108 个）**。新兴产业供应商优先挂 X 码，不要挤进父中类。
- 命中**行业词**（"医疗器械""纺织"）→ 挂**中类（group）**。
- 只能判到大类 → 允许挂 `division`，confidence ≤0.7 并进待精化。

**主行业码选择：证据最强、层级最深、置信度最高的那个。**
⚠ 现行参考实现（`apply_rules.mjs`）用 `MIN(industry_code)` 回填主码，是无语义的临时口径，接管后改为按证据选择。
